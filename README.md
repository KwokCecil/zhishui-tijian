# 智税体检（TaxCheckup）

> AI × 税务：模拟"金税四期视角"的企业税务自查工具。
> 输入企业的发票、资金、合同等模拟数据，输出**风险画像（评分 + 等级 + 命中特征 + 监管视角 Top3）+ 优惠政策清单 + 行动建议**。

🔗 **在线演示**：https://tax-checkup.streamlit.app
（Streamlit 免费版闲置会休眠，首次打开约需 30 秒冷启动）

## 这个工具解决什么问题

企业真正的痛点不是"我有没有问题"，而是"税务机关可能觉得我哪里有问题，而我自己不知道"。

金税四期的核心是"以数治税"：发票、资金、申报、社保、上下游数据全部打通，风险不再由单点异常触发，而是靠特征组合命中。但它的具体模型和阈值不公开，企业只能依据公开可见的风险逻辑做自查。

这个工具把公开可见的风险逻辑做成一份"自查版"：录入数据 → 规则引擎给出命中特征与证据 → 政策模块筛出可享受的优惠 → 生成可下载的体检报告。**判断全部由规则完成，模型只负责表达**；定位是企业自查工具，不是监管工具。

## 核心能力

- **风险特征库**：33 条原子规则 + 5 条组合规则，每条规则一个函数，输出统一结构 `{rule_id, name, hit, level, evidence, suggestion}`
- **证据可溯源**：每条结论都带特征编号与具体命中数据；组合规则命中时，构成规则并入组合结果，不重复计分
- **政策机会筛查**：8 张政策卡片（文号已逐条在官网核对），输出可享受 / 需人工确认 / 不适用
- **Agent 工具层**：规则、政策、小微判定包装成 function calling 标准工具，模型只做调度与表达；回答以结构化方式提交（结论 / 事实 / 动作 / 需补充数据），事实由系统按规则库填充
- **双模式运行**：未配置 API key 也能完整演示——离线模式用关键词路由直接调用工具

## 架构与关键设计

| 层 | 组件 | 职责 |
|---|---|---|
| L0 数据层 | 政策卡片 JSON + 生成器 + 上传 CSV | 存事实与输入 |
| L1 处理层 | pandas 读取、清洗、计算指标 | 把原始数据变成判定所需的指标 |
| L2 规则层 | 规则函数 + 评分函数 | 输出"命中/未命中 + 级别 + 证据" |
| L3 编排层 | function calling Agent | 调度工具、组织回答，不参与判定 |
| L4 界面层 | Streamlit | 上传数据、展示报告与对话轨迹 |

四条设计原则：

1. **事实与生成分离**：政策事实与特征规则只存在于数据层，模型无法改写判断
2. **判断确定化**：风险与优惠条件由代码判定，可解释、可测试、可留痕
3. **结构化提交**：对话回答通过 `submit_answer` 提交结构化结果，事实内容由系统按规则库 evidence 填充——模型既写不出建议当事实，也编不出不存在的规则编号
4. **多层兜底**：在线失败降级离线、报告失败回落模板、回答清洗、工具名不外泄

## Agent 工具层

工具 = 税务知识。判断全部封装在工具里（规则 / 政策卡片 / 小微判定），LLM 只负责理解意图、决定调用哪个工具、把事实组织成回答。

| 工具 | 输入 | 输出 |
|---|---|---|
| run_tax_health_check | profile + 发票/资金/合同 JSON | 命中特征 + 评分 + 等级 + Top3 |
| match_policy_cards | profile | 优惠政策清单（可享受/需确认/不适用，带文号） |
| check_small_micro | profile | 小微四项条件逐项判定 |
| answer_policy_question | query | 未收录政策的统一拒绝（引导 12366） |
| get_demo_scenario | clean/risk/fuel/solar/lotus | 内置场景四类数据 JSON |
| generate_report | hits + summary + matched | Markdown 体检报告 |
| submit_answer | conclusion + facts/actions/need_info | 结构化对话回答（结论/事实/动作/需补充数据） |

两种运行模式：

1. **离线演示模式（默认，无需 key）**：关键词路由直接调用工具，页面展示"意图→工具→事实→回答"的完整轨迹，用于演示和开发调试
2. **在线 Agent 模式**：配置模型 API 后，由模型自主决定调用哪些工具（真实 function calling 循环），并带最近 4 轮对话上下文

配置环境变量（或 Streamlit secrets）：

```bash
set ZHI_SHUI_LLM_API_KEY=sk-xxx
set ZHI_SHUI_LLM_BASE_URL=https://api.deepseek.com/v1
set ZHI_SHUI_LLM_MODEL=deepseek-flash
```

兼容任何 OpenAI 格式的模型服务（DeepSeek、通义、豆包、硅基流动等）。

## 场景说明

| 场景 | 用途 |
|---|---|
| clean | 全正常数据，应输出低风险画像 |
| risk | 软件企业混合风险种子（税负率低/三流不一致/个税社保差异/上游走逃/顶额开票/红冲偏高/小微临界等） |
| fuel | 加油站模板（申报340吨、设备350吨、测算480吨、区域参考440吨；以进控销 + 三源比对 + 设备信任梯度） |
| solar | 光伏设备制造企业：约120人、资产未临界、收入上亿、应税所得 292.7 万（距300万仅7.3万）、研发加计 600 万（小微临界预警链） |
| lotus | 农产品收购发票：收购对象身份存疑 + 单户金额异常 + 业务流不匹配 |

页面顶部会显示当前场景的**企业画像、风险种子、预期结论**，跑完自动给出"关键结论"横幅（最高关注特征 + 等级）和四项指标卡。

## 评分口径

- **风险指数（0-100，越高越危险）** = 命中规则点数之和（封顶100）
- 点数：高危 60、中危 30、低危/提示 10
- 分级标准：低危=非常常见、单看不能下结论；中危=很可能异常但可合理解释；高危=几乎可断定违法或直接证据
- 等级由指数直接推导：≥60 高风险；30-59 中风险；<30 低风险
- 预警原则：一条高危或两条中危即触发高风险
- 规则层级：组合规则用 G 系列独立编号、单独执行（G001-G005 已实现）；命中时构成规则并入组合结果不重复计分
- 规则分类：R + 三位编码 = 第一位业务大类 + 后两位序号（R=Rule），涵盖发票 / 资金 / 上下游 / 申报 / 人资信用 / 资格优惠 / 数据质量 / 行业模板 / 关联团伙；只登记已实现规则
- 政策互斥：P101 小微低税率与 P102 高新 15% 互斥，同一所得择优适用（小微 5% 更优）
- 风险-政策联动：P101/P301↔R601/G001/R604、P102↔R605、P103↔R603，命中相关风险时提示"享受前提"，所有场景通用
- 六税两费适用对象：小规模纳税人、个体工商户、小型微利企业；P104 负面清单为限制规则，命中=不得享受，未触发=不影响
- 例：案例一命中 G001(30)+R604(30)=60 → 高风险（R601/R602 已并入 G001）；案例六命中 G004(60) → 高风险（R804/R805 并入 G004）

## 规则输出结构

```json
{
  "rule_id": "R401",
  "name": "增值税税负率异常",
  "hit": true,
  "level": "高",
  "evidence": "税负率1.0%，行业参考下限3.0%",
  "suggestion": "核对进项抵扣与申报口径；演示阈值为公开口径，生产环境需校准"
}
```

## 适用范围与边界

- 金税四期的具体模型、阈值、权重不公开。本工具使用**公开可见的风险逻辑 + 演示阈值**，定位是**企业自查工具**，不是监管工具
- 所有数据为模拟数据，非真实企业；报告含免责声明
- 判定全部由规则完成（可解释、可测试、可留痕），模型只做表达
- 不做法律后果定性：不输出处罚测算与违法定性；涉及认定的事项（如高新技术企业资格）注明认定权归属，处置只给企业自查动作（核对、留证、补正、咨询）
- 生产环境需按地区、行业、主管税务机关口径校准阈值
